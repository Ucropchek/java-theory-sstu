Главные коллекции у нас динамические массивы (Lisе, ArrayList) и хэш-таблицы 
- Map<>
- HashMap (хэш-таблицы)
- TreeMap (красно-черное дерево)
- Map (ассоциативный массив, словарь)

```java
// ключ - значение
// ключ - уникальное
Map<String, String> phoneBook = null;
phoneBook.put("Masha", "+79110003355");
phoneBook.put("Anna", "+79110003365");
phoneBook.put("Elena", "+79110003385");
```

**Если элемента нет, то добавляется элемент, а если уже есть, то заменяется.**
*Индексов как в листах нет*

```inMap
[Anna:+79110003365, Elena:+79110003385, Masha:+79110003355]
```

```java
phoneBook.put("Masha", "000");
```
```inMap
[Anna:+79110003365, Elena:+79110003385, Masha:000]
```
В результате put() мы получаем результат типа данных который был помещен туда. Если мы туда положили, а там еще ничего не было, то возвращается null

```java
phoneBook.get(key);
remove(key);
contains(key);
```

~~`for(String str : phoneBook)`~~ так как Map не относится к коллекциям напрямую

```java
for(String str : phoneBook.keySet()) {
	phoneBook.get(str); // получили только ключ
}
```
```java
for(String str : phoneBook.values()) {
	phoneBook.get(str); // получили только значение
}
```
```java
for(Entry<String, String> node : phoneBook.entrySet()) { // получение всего сразу
	node.getKey(); // вытянули ключ
	node.getValue(); // вытянули значение по этому ключу
}
```

Хэш-код еще дополнительно хэшируется под капотом, поэтому в один бакет все попасть практически не может

**Если кол-во добавленных элементов стало 3/4 от кол-ва бакетов, то происходит увеличение кол-ва бакетов в 2 раза**
---

Диапазон хэшей проще пересчитывать, используя степени 2
Поэтому, если мы объявляем хэшмапу на 200 элементов бакетов 256

Первый параметр - кол-во бакетов
Второй параметр - при какой доле расширяется кол-во бакетов
3/4 идеальный баланс между скоростью чтения и вместимостью в бакете чаще всего

```java
Map<String, String> phoneBook = new HashMap<>(16, 0.75f);
```

Если не переопределять hashCode(), когда мы прописываем equals, то будет очень больно работать с мапой

Если использовать в качестве ключа изменяемый объект, то при первом же изменении будет невозможно достучаться до МММаши из хэшмапы, потому что у нее уже другой хэш-код

По хэш-мапе можно проходиться и классическими итерируемыми способами (getValues)

ЕСЛИ в мапе не менее 64 нод И в одном бакете не меняем 8 нод, ТО такой бакет из связного списка превращается в красно-черное дерево

## LinkedHashMap

![[Pasted image 20261116110838.png]]
вся хэш-мапа еще дополнительно превращается в связный список как на картинке

```java
class HashMap {
	class Node<K, V> implements Entry<K, V>{
		K key;
		V value;
	}
}
```

```java
class LinkedHashMap {
	class Entry<K, V> extends Node<K, V>{
		Node<K, V> nextNext???;
	}
}
```

```java
Map<String, String> phoneBook = new LinkedHashMap<>(16, 0.75f, true); // 3 параметр  это accessOrder
phoneBook.put("Masha", "+79110003355");
phoneBook.put("Anna", "+79110003365");
phoneBook.put("Elena", "+79110003385");

```

boolean accessOrder - у нас доступ в порядке добавления или в порядке доступа
