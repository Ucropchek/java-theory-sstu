
Наследование оправдана при:
1. Шаблонизация
2. Множества подмножества (Is-A)
```java
void main() {
	/*
	1) квадрат прямоуглольник
	2) стэк и список
	*/
	abstract class Figure {
		abstract double area();
	}
	
	class Circle extends Figure {
		@Override
		double area() {
			return 0;
		}
	}
	
	class Square extends Rectangle {
		public Square() {
			super.(a, a);
		}
	}
	
	class Rectangle extends Figure {
		int a,b;
		@Override
		double area() {
			return a*b;
		}
	}
}
```

Набор состояний должен быть задан родителем. Если наследник добавляет поля, то скорее всего это не очень

НИКОГДА не использовать Stack, потому что он наследован от ДМ

Стек реализуется на двусторонней очереди

Если наследование не нужно:
1. Отказ от наследования
2. Переделать иерархию и продумать состояние
