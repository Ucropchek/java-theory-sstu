```java
class A{

		System.out.println("Hello");
	}
}

class B extends A{
	void m2(){
		System.out.println("Hello from B");
	}
}
```

2. Философия наследования

У наследования есть ряд обязательств

Наследование может привести к проблемам, надо знать когда

```java
class A{
	...
}

class D{
	...
}

class B extends A, D{ // нельзя
	void m2(){
		System.out.println("Hello from B");
	}
}
```

Наследование представляет собой иерархию
Если не указать родителя, то любой класс наследуется от Object

Если у родителя что-то есть, то и у наследника это СТРОГО есть.

```java
class A{
	B b = new B();
	void m(){
		System.out.println("Hello");
	}
}

class B extends A{
	void m(){
		System.out.println("Hello from B"); // переопределение родительского метода
	}
}
```

Через super можно обратиться к родительскому методу даже переопределив метод.

```java
class A{
	B b = new B();
	void m(){
		System.out.println("Hello");
	}
}

class B extends A{
	void m(){
		super.m() // родительский метод
		System.out.println("Hello from B" + B.this.x); // переопределение родительского метода
	}
}
```

Переопределение на полях не существует.
B.this.x тоже самое что x внутри наследника при затемнении поля (шедуинге)

Не надо шедуить поля не зная что делаешь

Наследник в конструкторе ВСЕГДА неявным образом обращается к классу родителя

При вызове конструктора наследника вызовется super()
Выполнится все блоки инициализации родительского класса

Статика родителя --> статика наследника --> конструктор родителя (`super()`) --> конструктор наследника

```java
static A
static B
this method B
super A
after super
after this
```

## Абстрактные классы

Обычные классы с полями и методами, но у такого класса нельзя создать объект

```java
SuperParent sp = new SuperParent; // ошибка
```

Абстрактные классы созданы для наследования, а не для инициализации

Абстрактные классы отличаются синтаксисом.
У них нет тела.

```java
abstract class SuperParent{
	String tmp;
	abstract void m();
}
```

Абстрактные методы не имеют тела, а наследник обязан реализовать метод (уже без `abstract`)

Модификатор доступа нельзя сужать у наследника

У абстрактного класса может быть конструктор для базовой реализации и он вызовется при super(<параметры, предусмотренные в родительском конструкторе>)
