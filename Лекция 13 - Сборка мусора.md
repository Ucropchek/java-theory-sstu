## Метод clone()

```java
@Override
protected Object clone() throws CloneNotSupported {
	return super.clone();
}
```

```java

public void Main() {
	Point point = new Point();
	Point point1 = point.clone();
}
```

clone() стремный
==🔴Нельзя ни в коем случае приносить clone(), который возвращает new YourClass(YoutrClass);==

Надо заявить что целевой класс реализует интерфейс **Cloneable**

Из-за ошибки архитектуры первых версий интерфейс используется как маркер клонирования

Если попытаться вызвать 

Чтобы сделать пометку сущности надо делать по современному и правильному подходу ==аннотации==
*==🟢Например @Override==*

```java
@Override
public Point clone() {
	try {
		return (Point) super.clone();
	} catch (CloneNotSupportedException e) {
		throw new RuntimeException();
	}
}
```

```java

public void Main() {
	Point point = new Point(1, 1);
	Point point1 = point.clone();
	point.setX(999); // сетает обоим
}
```

Так как наш поинт теперь состоит из ссылочного поля coords, то clone() копирует ссылку на массив в поле класса-клона

```java
@Override
public Point clone() {
	try {
		Point point = super.clone();
		point coords = this.coords.clone();
		return point;
	} catch (CloneNotSupportedException e) {
		throw new RuntimeException();
	}
}
```
/\
 |
 теперь клонирование не дублирует координаты оригинала **после копирования** (сет не меняет копию)

**==🟠Мы создаем объект в обход конструктора, что неприятно==**

```java
List<Integer> nums = List.of(1, 2, 3); //нет clone() для List
ArrayList lst = null;
lst.clone() //есть
```

так нельзя делать потому что непонятно, примитив в листе или ссылочный тип и как вообще клонировать нормально
*Поэтому надо делать ручное копирование циклом*

## finalize()

```java
public void Main() {
	Point point = new Point(1, 1);
	Point point1 = point.clone();
	point.setX(999); // сетает обоим
	
	point = null;
	System.gc(); // Просьба попросить сборщика мусора убрать мусор, если можно
	System.out.println("delete garbage");
}
```

finalize - аналог деструктора, но херня в том, что непонятно когда сборщик вообще за него возьмется

Этот метод может выступать в качестве страховки, но только в качестве лога в консоли, у нас даже не получится там Exception кинуть

При переопределении finalize() замедляется сборка мусора
