# Конструктор

При создании объекта автоматически обращается к конструктору объекта

```java
void main() {
	ArithmeticExpression e = new ArithmeticExpression();
}
```

В bytecode есть только init. Java обращается к методу конструктора. Конструктор выделяет память и, что мы пропишем в конструкторе, выполниться автоматически при создании объекта.

```java
class ArithmeticExpression {
	public ArithmeticExpression{
		ArrayList<Integer> value = new ArraList<>();
	}
	...
```

инициализация может быть inline, inblock и конструкор

```java
{ code } // inblock
```

this(); - вызов своего же конструктора

this означает, что вызывается что-то внутри класса

есть статические блоки инициализации. используются для инициализации чего-то для класса только

static init ---> block init ---> construct

Чтобы не копипастить код в конструкторе можно сделать цепь конструкторов

```java
public ArithmeticExpression() {
	ArrayList<Integer> value = new ArraList<>();
}

public ArithmeticExpression(int value) {
	this.value = value;
}

public ArithmeticExpression(String str) {
	this(); // переходим в конструктор, который не принимает ничего
	this(1); // переходим в конструктор, который принимает число
}
```

Если конструкторы выполняют не связанные друг с другом вещи, то они не должны быть в конструкторе и наоборот

Конструктор без параметров должен быть верхним
	Конструктор - это говно
Порождающий класс заменяет конструктор
В конструкторе нельзя управлять процессом создания объекта, потому что new просто инициализирует
