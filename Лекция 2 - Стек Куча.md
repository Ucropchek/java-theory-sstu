утекший участок - мусор

Сишный стиль предполагает написание кода так, чтобы утечек в принципе не было

В Java мусор выбрасывается сам

```java
int[] arr = new int[5];
arr = null;
```

null - специальный тип данных предназначенный для того, чтобы показать, что ссылка никуда не ведет

Идет интерпретация (thread Main)
параллельно идет сборка мусора являющаяся подпрограммой (thread garbage collector)
garbage collector отрубают, потому что он замедляет исполнение параллельностью процессов
В конце программы просто сжигают все к херам (и программу и мусор)

Сборка мусора не происходит постоянно, а только тогда, когда он накапливается

**gc root**

# Примитивные типы

```java
int x = 3/0; // ArifmeticExeption
int x = 0xCAFE_BABE;
//0x 0o 0b 16 8 2
byte b = 5; <=> byteb = (byte) 5;
byte b = 300; <-- ошибка компиляции, а byte b = (byte) b; норм
```

```java
float f = 3/0; // ArifmeticExeption
float f = 3/.0; // +Inf
float f = 3.0; // ошибка типа данных
float f = 3.0f;
double d = 3.0;
```

1. Целочисленные (дополненные кода, -x...+(x-1))
	1. byte - 1
	2. short - 2
	3. int - 4
	4. long - 8
2. Вещественные числа (IEEE754   -Inf...-0 0 +0...+Inf NaN)
	1. float - 4
	2. double - 8
3. Логический
	1. boolean (true/false) нет четкого размера
4. Символьный
	1. char - 1 (беззнаковый, нельзя взаимно приводить к числовым типам, потому что они знаковые)
```java
short sh=5; // like
char ch=5; // like
sh=ch; // error
ch=sh; // error
```
