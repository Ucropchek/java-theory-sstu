**Полиморфизм** (*полиморфный вызов метода*) - это способ написание кода через использование механизма, где ссылка определяет, что доступно, а объект определяет как работает

Абстрактные классы нудны только для наследования
Интерфейсы нужны для дополнительных функций

Поля не могут и не должны относиться к интерфейсу
Конструктор не нужен в интерфейсе
слово abstract подразумевается, но его можно не писать

в классе, который мы заимплементили мы **обязаны** реализовать все методы интерфеса

Для каждого класса нужно продумывать иерархию, способы взаимодействия

```java
...	
	List<Integer> grades = new ArrayList();
...
```

Это интерфейс существует для реализции наших методов, а не наоборот

В интерфейсе можно объявлять константы, но вас захерачат
Можно делать статические методы в интерфейсе с **реализацией**

```java
public interface Rule {
	public static final EMPTY = new AllTrue();
	public static Rule ofEmpty() {
		return EMPTY;
	}
	static Rule ofRange() {
		return new RuleRange(min, max);
	}
	boolean check(int x);
}
```

Методы с дефолтной реализацией необязательно реализовывать в классе

```java
public interface Rule {
	public static final EMPTY = new AllTrue();
	public static Rule ofEmpty() {
		return EMPTY;
	}
	static Rule ofRange() {
		return new RuleRange(min, max);
	}
	boolean check(int x);
	public default void method () {
		...
	}
}
```

Интерфейсы можно множественно имплементрировать, НО
несколько одинаковых методов из разных интерфейсов **нельзя не определить**

```java
pulic void checkWithCode(int x) {
	Rule.super.checkWithCode(x);
}
```

**Множественное наследование разрешено для интерфейсов**

если класс имплементит дочерний интерфейс, то он должен реализовать все методы и дочерние и родительские.

Дефолтную реализацию в родителе можно сделать просто методом в дочернем интерфейсе
