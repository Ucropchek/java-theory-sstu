### Порождающие
Объект порождается не напрямую, а через приватный конструктор и 2 варианта дальше:
- статический инициализатор
- класс реализующий порождение

Singleton:
Жадный (объект создается каждый раз):
```java
public class StringComparator implements Comparator<String> {
    private static StringComparator comparator = new StringComparator();

    private StringComparator() {}

    public static StringComparator getInstance() {
        return comparator;
    }

    @Override
    public int compare(String s1, String s2) {
        return s1.length() - s2.length;
    }
}
```
Ленивый (создает объект при):
```java
public class StringComparator implements Comparator<String> {
    private static StringComparator instance;

    private StringComparator() {}

    public static StringComparator getInstance() {
        if (instance == null) {
            instance = new StringComparator();
        }
        return instance;
    }

    @Override
    public int compare(String s1, String s2) {
        return s1.length() - s2.length;
    }
}
```
Ленивый (отложенная инициализация Proxy): 
```java
public class StringComparator implements Comparator<String> {
    private static class StringComparatorLazyInitiolizer implements Comparator<String> {
        private StringComparator comparator;

        @Override
        public int compare(String s1, String s2) {
            if (comparator == null) comparator = new StringComparator();
            return comparator.compare(s1, s2);
        }
    }

    public static Comparator<String> getInstance() {
        return new StringComparatorLazyInitiolizer();
    }

    @Override
    public int compare(String s1, String s2) {
        return s1.length() - s2.length();
    }
}
```

### Поведенческие
Поведение - это тоже объект (вынесенный в класс за класс в котором задача)
*Итератор тоже поведенческий паттерн*
В зависимости от задачи есть разные итераторы
Только один из поведенческих шаблонов реализует наследование

- Proxy
- Buider
- Singleton
